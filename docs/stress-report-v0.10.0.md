# 压力测试报告（LG-011，v0.10.0）

> 工具：`scripts/stress-headless.ps1`（N 个模拟客户端并发轮询 + 心跳 + 运行中发布新策略）。
> 环境：单机（客户端与服务端同机，走 127.0.0.1，**不含真实局域网 RTT**）；Windows 10 19045 / .NET Framework 4.8。
> 说明：本报告是**短基线**（各 2–3 分钟），计划 §C4 要求的是"100 客户端 30 分钟"——长时间跑应在真实机房或两台独立机器上复测。

## 结果

| 指标 | 100 客户端 × 180s | 200 客户端 × 120s | 计划通过条件 |
|---|---|---|---|
| 请求成功 / 失败 | 3600 / **0** | 4800 / **0** | 无崩溃、无死锁 |
| `/api/version` 延迟 p50 / p95 / max | 0.7 / **7.8** / 91.8 ms | 0.7 / **11.1** / 221.2 ms | 单客户端不显著阻塞他人 |
| 发布新策略后 p95 可见耗时 | **1.08 s**（max 1.1 s） | **1.5 s**（max 4.99 s） | 95% ≤ 10 s ✅ |
| 服务端内存 before → after | 33.5 → 43.2 MB（+9.7） | 33.5 → 43.6 MB（+10.1） | 无持续增长 |
| 服务端存活 | ✅ | ✅ | ✅ |
| 心跳被限速（429） | 570 | 760 | 见下"同 IP 限速" |

- 发布路径：**运行中**用服务端 CLI 保存策略（写磁盘）→ 服务端靠"磁盘热拾取"自动切换（无需重启）。
  两轮发布（seq 递增）都能在 5 秒轮询周期内被绝大多数客户端看到。
- 429 全部来自**同一 IP 的并发心跳**（模拟机都在 127.0.0.1）；真实机房每台学生机一个 IP，
  60 秒一次心跳远低于"同 IP 每秒 5 次"的限制。客户端被限速时按正常周期退避，**不影响策略下发**。

## 复现

```bat
powershell -File scripts\stress-headless.ps1 -Clients 100 -Seconds 180
powershell -File scripts\stress-headless.ps1 -Clients 200 -Seconds 120 -SkipBuild
```

每次运行会在数据目录留下 `stress-report-<客户端数>-<端口>.json`（本仓库的结论就是这些 JSON 的汇总）。

## 结论与后续

- 100 与 200 客户端两个档位**全部 5 项断言通过**，且余量很大（p95 延迟 < 12 ms、策略可见 p95 < 2 s）。
- 待补（真实环境）：① 两台独立机器（含交换机/无线）测真实 RTT；② 计划要求的 30 分钟长跑；
  ③ 教师机 UI 在压力期间的人工可用性确认（本轮以 `/api/version` 探针延迟作为代理指标）。

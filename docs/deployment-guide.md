# LabGuard v0.10.0 部署指南（教师机 + 学生机）

> 目标读者：机房老师 / IT 管理员。全程只需要两个 exe 与一个配对文件，**不联网、不装数据库**。
> 配套版本：教师机服务端 `LabGuardServer-Setup-v0.10.0.exe`，学生机 `LabGuard-一键安装程序.exe`（v0.10.0）。

## 0. 先理解三件事

1. **教师机是"策略中心"**：策略在教师机上编辑、签名，学生机定时来取。教师机不在网，学生机**继续执行最后一份策略**（不会失控）。
2. **学生机只认签名**：策略带 RSA 签名 + 单调序号，伪造服务器、篡改策略、重放旧策略在数学上过不去（这是它与"随便一个 HTTP 服务"的本质区别）。
3. **配对 = 把教师机的公钥 pin 到学生机**：一台学生机只信它配对过的那台教师机。换教师机要重新配对。

## 1. 教师机部署（约 3 分钟）

**前置**：Windows 7 及以上 + .NET Framework 4.8（Win10/11 自带；安装程序会自检并给出提示）。

1. 把 `LabGuardServer-Setup-v0.10.0.exe` 拷到教师机，**双击**（会请求管理员权限）。
2. 界面里点【① 安装教师端】。安装程序自动完成：
   - 装到 `C:\Program Files\LabGuard Server`；
   - 配置 **HTTP URL ACL**（没有它，非管理员/服务身份无法监听局域网端口，学生机会连不上）；
   - 添加**入站防火墙规则**（TCP 8210）；
   - 创建桌面快捷方式与**登录自启**；
   - 启动服务端并自检监听。
3. 托盘出现图标（作者头像 + 黑底）。右键 →「策略面板」——**面板不要求密码**（见文末「安全边界」）。
   面板按**「谁执行」分三层**（见 §2.1 职责归属）：左栏是三层树，每组后面写着"23 项 · 改 2"，
   一眼看出哪组动过；顶部搜索框可跨全部组搜关键词（如 `USB`、`DNS`、`任务管理器`）；
   改过的开关左侧有蓝条，旁边有「恢复默认」。
4. 改完点【保存并下发】→ 会先弹出**差异清单**（这次改了什么，旧 → 新）确认后才下发。
   **这一步之后学生机才有策略可取**（此前 `/api/version` 返回 503 属正常）。
5. 右键 →「导出配对文件」→ 得到 `labguard-pairing.json`，界面会显示**公钥指纹**（形如 `de033d6567515018`），记下来，学生机上要核对。

无人值守安装（一条命令，适合批量/脚本部署）：

```bat
LabGuardServer-Setup-v0.10.0.exe --install --dir "C:\Program Files\LabGuard Server" --port 8210
LabGuardServer-Setup-v0.10.0.exe --status                 :: 查看安装状态与监听自检
LabGuardServer-Setup-v0.10.0.exe --export-pairing D:\pairing.json
```

## 2. 学生机部署（约 1 分钟/台）

### 2.1 职责归属：谁执行、谁决策（v0.10.3 起写进界面）

**教师端不执行任何管控动作**——它只做四件事：编辑策略 → 签名 → 下发 → 看在线状态。
所有管控（上网/DNS/USB/浏览器/任务栏/电子教室保护/进程防拆…）**全部由学生机上的程序执行**。
因此策略面板按"谁执行"分三层，避免老师把"学生机自己的自保"当成"我这节课要调的开关"：

| 层（面板左栏） | 谁执行 | 谁决策 | 分组 |
|---|---|---|---|
| **课堂管控** | 学生机 | 老师（下发） | 总体、网络与防火墙、集中 DNS、违规软件拦截、新文件/下载监控、USB、hosts 黑名单、浏览器、任务栏与系统工具、安全模式与启动菜单 |
| **学生端自保与环境** | **学生机自己** | 装机时定一次 | **电子教室保护**、机位标识、注册表权限加固、互相守护、**进程防拆加固** |
| **教师端自身** | 学生机本机 | 学生机本机 | 服务器统一管控（地址/轮询/心跳）——**不下发给学生机，面板里不显示**；配对用 `install.ps1 -Pair` 或 `--pair` |

> 为什么这么分：`电子教室保护`（保住极域/红蜘蛛/锐捷/噢易不被学生脱离）和 `进程防拆加固`
> （小助手杀不掉、被杀秒级复活）是**学生机在保自己**，不是老师的日常操作；关掉它们等于放弃学生机的自保能力，
> 面板会把这一层单独折叠并给出后果提示。

**前置**：Windows 7 及以上 + .NET Framework 4.8；需要**管理员**权限。

1. 把 `LabGuard-一键安装程序.exe` 与教师机导出的 `pairing.json` 拷到学生机。
2. 双击安装（向导：欢迎 → 位置 → 密码 → 功能开关 → 安装）。
3. 装完后**配对**（任选一种）：
   - 图形：`LabGuard.Settings.exe` 面板里导入配对文件；
   - 命令行：`LabGuard.Settings.exe --pair D:\pairing.json`；
   - 或者安装时直接带参数（推荐批量用）：见下面一条命令。
4. 核对：`LabGuard.Settings.exe --server-status` 应显示**已配对 = True**、教师机地址、以及
   `同步状态 = Polling · seq N · 最近同步 …`。

批量/无人值守（一条命令完成"安装 + 配网信任"）：

```bat
LabGuard-一键安装程序.exe --silent --password 你的口令123 ^
    --config D:\presets\机房预设.json ^
    --pair D:\pairing.json
```

也可以装完后再配对：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -Password 你的口令123 -Pair D:\pairing.json
```

> **导入配对会自动清掉本机的「暂停监控」标记**——这是设计：配对了就表示"这台机器交给教师机统管"。
> 如果某台机器临时要脱离管控，在它本地的设置面板/托盘里点「暂停监控」即可（服务器策略会被暂存，恢复后自动应用）。

## 3. 日常使用

| 场景 | 怎么做 |
|---|---|
| 改策略 | 教师机 → 策略面板 → 改开关 → 【保存并下发】。学生机默认 5 秒轮询，**健康局域网内 ≤10 秒生效** |
| 上课/下课统一暂停 | 教师机策略面板 →【全员暂停】/【全员恢复】（暂停 = 停止管控策略；进程守护照旧） |
| 看谁在线 | 教师机托盘 →「在线学生机」：机器名 / IP / 客户端版本 / 策略 seq / 是否暂停 / 最近心跳 |
| 看"哪台还没用上新策略" | 教师机托盘 →「设备与策略状态」（v0.10.4）：每台显示 **已应用 / 待应用 / 应用失败 / 版本不一致 / 疑似克隆 / 在线（旧客户端）/ 离线**，顶部给汇总计数 |
| 按机房/班级分组下发（v0.11） | ① 托盘 →「设备分组…」→ 新建组 → 勾选成员（设备列表来自心跳，能看到"当前分组"）→ 保存成员；② 回到**策略面板**，顶部「下发目标」选这个组 → 改完点【保存并下发】。该组设备 5 秒内生效，**其他设备不受影响**；底栏会显示"目标 N 台，已应用 M 台" |
| 某台机器临时人工干预 | 在**该学生机**上暂停监控（托盘或设置面板）。服务器策略会暂存，恢复后自动应用 |
| 换教师机 | 新教师机装好后导出配对文件 → 每台学生机重新 `--pair`（旧公钥会被替换） |
| 解除某台学生机的管控 | 学生机执行 `LabGuard.Settings.exe --unpair`（回到单机版行为） |

## 4. 排障

| 现象 | 先看什么 | 处理 |
|---|---|---|
| 学生机一直"回退单机" | 教师机 `netsh http show urlacl` 有没有 `http://+:8210/`；防火墙规则在不在；教师机与学生在同一网段 | 重跑安装程序（URLACL/防火墙是安装步骤，会重新配好），或手动：`netsh http add urlacl url=http://+:8210/ user=Everyone` |
| 教师机上看不到学生机 | 学生机 `--server-status` 的地址对不对（配对文件里是教师机当时的 IP） | 教师机换过 IP：在教师机重新导出配对文件并到学生机重新 `--pair` |
| 学生机策略没变 | 学生机服务在不在跑；`server-state.json` 的 `appliedSeq` 与教师机策略面板显示的 seq | 教师机没保存过策略（503）→ 先在策略面板保存一次 |
| 学生机显示"服务器全员暂停中" | 教师机策略面板的暂停状态 | 教师机点【全员恢复】 |
| 想看详细日志 | 教师机：`C:\ProgramData\LabGuardServer\logs\`；学生机：`C:\ProgramData\LabGuard\logs\` | 日志不含口令与私钥，可直接发给管理员排查 |
| 日志里有 `429` | 服务端对 `/api/checkin` 限速：**同一 IP 每秒最多 5 次**（防伪造心跳淹没） | 正常机房每台学生机一个 IP、60 秒一次心跳，不会撞限；若整个机房经 NAT 走同一个 IP 且集中开机，可能出现 `429` —— 客户端会自动在下个周期重试，**不影响策略下发** |

## 5. 卸载

| 侧 | 命令 | 说明 |
|---|---|---|
| 教师机 | `LabGuardServer-Setup-v0.10.0.exe --uninstall` | 删程序 + URLACL + 防火墙 + 自启快捷方式，**保留密钥/策略**（换机重装可继续用同一把密钥，学生机不用重新配对） |
| 教师机（彻底） | `LabGuardServer-Setup-v0.10.0.exe --uninstall --purge` | 连密钥与策略一起删（下次安装生成新密钥 → 所有学生机要重新配对） |
| 学生机 | 开始菜单 →「卸载」（需要口令） | 常规卸载，逐项还原系统 |
| 学生机（救援） | `powershell -File cleanup-all.ps1 -Force` | **老师自己介质上的脚本**：程序被破坏、密码忘了、卸载器没了都能收尾；安全模式下也能跑 |

## 6. 版本与升级

- 教师机与学生端**同版本号同日发布**（本版 = `v0.10.0`）；学生机上报的 `version` 会显示在在线列表里。
- 升级学生端：直接覆盖安装新版本（配置与配对保持不变）。
- 升级教师端：直接覆盖安装（`--install` 会先停旧进程再替换文件，密钥/策略/配对记录保留）。
- 协议不兼容时学生机会**拒绝该信封并保留现有策略**（日志给出原因），不会因升级失控。

## 7. 合规边界（明确不做）

## 6.5 安全边界（v0.10.1 起策略面板免密，请务必读一遍）

策略面板**不再要求密码**：教师机由老师自己管制，改策略是高频操作，每次输密码不划算。
代价是**任何能碰到教师机的人都能改全场策略**（包括「全员暂停」）。因此：

- 教师机请按"只有老师能用"来管理：设好 Windows 登录口令、离开时锁屏（Win+L）、别让学生单独留在教师机前；
- 教室里的教师机如果是公共账号自动登录，建议把它放进"老师办公室/讲台内侧"这类受控位置；
- 若某个机房做不到上面两条，告诉我，我可以再加一个**可选的"面板口令"开关**（默认关，需要时才开）。

本软件**不做**远程桌面、屏幕监控、远程键鼠、截屏、录屏、文件传输与聊天；教师机与学生机之间只传
**签名策略信封**、**配对文件**（公钥/主机/端口/指纹）与**心跳状态**这三类固定结构的数据。

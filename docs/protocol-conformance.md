> 任务：**LG-003 协议实现对照审计**（执行计划 §5 B1 / §17 LG-003）。
> 方法：以 `docs/protocol-v1.md` 为唯一规范，逐条到实现里找出处，并核对**是否有自动测试**。
> 结论口径：`符合` / `文档已补`（实现没问题、规范写漏）/ `实现已修`（实现与规范不符）/ `待办`（留给后续任务）。

## 4. 信封与签名（协议 §2）

| 协议条目 | 实现 | 测试 | 结论 |
|---|---|---|---|
| 格式 `LGSRV1\|seq\|issuedAt\|paused\|policyJson\|signature`，前 4 个 `\|` 划头部、最后一个 `\|` 划签名 | `Envelope/PolicyEnvelope.cs: Parse` | 1.1–1.3 | 符合 |
| 签名 = RSA-2048-SHA256 / PKCS#1 v1.5，覆盖前五段 UTF-8 字节 | `PolicyEnvelope.Sign/Verify` | 1.1、1.4–1.6 | 符合 |
| `issuedAt` 规范化格式 = .NET `"o"`（UTC，7 位小数 + `Z`），属于被签名字节 | `PolicyEnvelope.SignedPayload` | 1.2 | 文档已补（原文只说"ISO-8601 UTC"，签名覆盖面里这种模糊会埋雷） |
| 未知魔数整封拒绝 | `Parse`（魔数不匹配即返回未验签） | 1.7 | 符合 |
| 篡改 `policyJson` / `paused` / 换公钥 → 拒绝 | `Parse` | 1.4–1.6 | 符合 |

| 私钥不得出现在配对文件 / 日志 / API | `PairingFile`（只导出 `ToXmlString(false)`）、日志不带密钥 | 2.2（密钥文件是 DPAPI 密文，不含明文 XML）+ 客户端侧 [10]②（含 `<D>` 段即拒绝导入） | 符合（服务端侧 API 不返回私钥；**诊断包脱敏 → LG-013**） |

## 5. seq 与防回滚（协议 §2、计划 §B2 不变量 4/5/8）

| 不变量 | 实现 | 测试 | 结论 |
|---|---|---|---|
| 4. `seq` 低于已接受值永不生效（客户端侧） | 客户端 `ServerClient`（`PolicyEnvelope.IsNewer`） | 客户端自检 [11]⑦ | 符合 |
| 7. 加载失败保留内存现行信封（服务端重载路径） | `PolicyStore.Load`（先验签后提交） | 4.12 | 符合 |
| 8. **服务重启后不得把 seq 回退到旧值** | **新增 `seq.highwater` 水位**：`Load` 用 `max(minSeq, 水位)` 作下限（重启路径同样生效）；`Save` 用 `max(CurrentSeq, 水位)+1` | **8.1–8.7（本轮新增）** | **实现已修**（原实现只在 `Load(minSeq)` 显式传参时才拦，启动路径不传 → 旧信封可让 seq 回退，并导致后续新策略 seq 撞车被客户端静默忽略） |
| 5. 相同 seq 但内容不同不得覆盖可信现行策略 | 客户端按 `seq <= 已应用值` 一律拒绝（不比内容） | 客户端自检 [11]⑤⑦ | 符合（口径：同 seq 即视为无更新） |

## 7. 本轮差异处置（计划 §B1 的四步：判错 → 加测试 → 改实现或文档 → 记 CHANGELOG）

1. **重启后 seq 回退（不变量 8）** → 判为**实现错误**（规范 §2.1 已承诺服务端防回滚）→
   新增水位 + 启动下限 + 保存不复用 seq；测试 8.1–8.7；文档新增 §2.2。
2. **落盘非原子** → 判为**实现错误**（计划 §B4 明确要求）→ 新增 `AtomicFile`；测试 8.8；文档新增 §2.3。
3. **`seq: 12.0` 被拒** → 判为**实现错误**（规范口径是"取值为非负整数"）→
   实现补 `decimal` 分支（有小数部分仍拒）；测试 5.16、5.17；文档改 checkin 表。
4. **空请求体 / 未定义方法 / 未知字段 / 请求编码 / 503 精确条件** → 判为**文档写漏** →
   实现不动，补测试 5.14、5.15、6.12，协议 §3 补齐。
5. **`issuedAt` 精确格式** → 判为**文档写漏**（它属于被签名字节）→ 协议 §2 写明 `"o"` 往返格式。
